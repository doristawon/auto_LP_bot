# 撤池後重新投入的復原工具

RPC 429 或價格變動可能讓已確認撤池的工作停在 `recovery_required`。
`node src/tools/resume-withdrawn-deposit.js` 只核對與預演，不送交易。

核對條件：單池模式、目標仍為原池、撤池收據成功且屬於該錢包與區間、舊份額為零、
目前餘額等於 journal 撤池後餘額、nonce 無待確認交易、沒有後續資金交易或未知廣播。
不符合任一條件便停止；不要手動清除 journal。

明確授權投入後，先暫停所有錢包並停止中控台 supervisor，確認其他交易沒有執行中，
再執行 `node src/tools/resume-withdrawn-deposit.js --execute`。
工具會拒絕仍在運行的本機中控台，以原 journal 接續一次 atomic swap＋deposit，
核對成功後解除 journal，並保持暫停，方便重新啟動中控台後檢查。
停損鎖定、私鑰與錢包不符、跨池或分配模式都不允許接續。
原停損基準不會改變。結果保存在本機忽略的 `artifacts/`；私鑰及 RPC 留在本機設定。

RPC 執行器依端點共用節流，包含兩錢包及讀寫 provider：最多兩個請求同時執行，
請求開始間隔至少 250 ms，不使用大批次。暫時性 429 的唯讀呼叫最多重試兩次，
等待 5／10 秒並讓同端點一起退避。廣播、未知方法與明確額度耗盡不重試；
未知廣播結果仍需要收據核對，不會盲目重新送出。
