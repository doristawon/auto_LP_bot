# PONS 自適應帶寬（net-yield-v2）

本策略只適用 PONS/USDG 的指定 PoolId，各錢包分開保存啟用設定。中控台「LP 部位與區間檢查」可開關。停用後恢復原 OOR 政策；保存設定本身不送交易。

## 參數與計算

- `K_CAL=2.9`、`LAM=0.22`、`LOOK_H=24`、`REB_MAX=6`。
- 由最近完整 24 小時 PoolManager Swap 算出 σ（tick/√小時）、drift（tick/小時）、每日手續費流與成交量加權平均費率。至少 20 筆，首尾成交須跨越 23 小時；不以短窗外推成一天。
- 以實際 tick、token decimals 與 USDG 為 1 美元計價，計算每個合法區間的單位流動性價值。未使用 tick=0 或兩幣相同 decimals 的假設。
- 枚舉 2–80 個 spacing：PONS spacing=60，故總寬 W=120–4800。奇數個 spacing 使用相鄰合法 tick，總寬保持精確。
- `reb=24×2.9×(σ²/(W/2)²+abs(drift)/(W/2))`；排除 `reb>6` 的候選。
- `gross=Fday×myL/(L_active+myL)`；`cost=reb×(0.5×avgfee+0.22×(1.0001^(W/2)−1))×size`。選擇 `gross−cost` 最大者。
- 若所有候選均不符合每日次數上限，保留現況並記錄原因，不以最大寬度冒充合格解。負的最高淨值不另設進場阻擋，符合使用者指定模型。

K 與 λ 是使用者提供的歷史校準參數，並非本專案獨立重做四天回測的結論。模型未額外計入 Gas、實際滑點或未反映於 Swap 的 Hook 費用，預估淨收益不等於實現損益。

## 實盤流程

1. 啟用後每 60 秒排程監控（掃描耗時可能延後）；完整 Swap 資料每小時更新。只掃指定 PONS，不掃全市場 Swap。
2. 區間內保留現有 LP，不為更新模型而換帶，也不自動補倉。明確的人工換倉與停損沿用各自流程。
3. 價格自然出區間且此部位持有滿一小時後，進場前讀取資金、Tick 與流動性。這個 PONS 政策取代舊 OOR 等待／超出百分比；其他池仍使用原設定。
4. 一次交易流程固定所選總寬，官方 reposition、withdraw/swap/deposit 與 atomic deposit 共用同一決策。價格移動時可重新置中，但不在流程中重選 W。
5. 已有完整退出但待復原的 journal 時不另開新倉。沒有任何 LP、指定池為 PONS，且沒有停損鎖定／暫停／未完成交易，才使用現有完整模擬與簽署流程建倉。
6. 歷史 LP 起算使用本機既有部位基準；無法證明持有時間時從首次有效觀測起保守計滿一小時。新再平衡完成後重新起算。
7. 資料缺漏、過舊、額度耗盡或 reorg 時暫緩重新投入，帳務與停損照常運作。停損不受一小時持有門檻限制。

## RPC 與資料界線

單次只允許 128 個 feed RPC 請求、10,000 筆事件、90 秒處理期限。部分 RPC 層可能另有端點切換；這個限制是 feed 的邏輯請求數。只有明確的區塊範圍／結果上限才切小範圍重試，額度或網路失敗不循環重試。首尾以真實區塊時間量測，沒有逐筆查區塊；檢查結尾區塊 hash，避免掃描期間重組。

Swap 輸入使用 V4 負向 BalanceDelta，費率分母為 1,000,000。非 USDG 輸入依該筆 USDG 輸出換算成交費。僅消耗 1 raw unit 且 USDG 輸出為 0 的零頭保留在價格樣本、排除於費用／成交量，並另計 `dustEvents`。

本機 state 記錄 `adaptiveRangeSettings`、`adaptiveRangeStats`、`adaptiveRangeDecision`；不包含 RPC URL 或私鑰。GitHub 僅發布程式、測試及文件，不發布本機 state、實際錢包資料或憑證。
